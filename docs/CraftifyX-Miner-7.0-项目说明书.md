# CraftifyX Miner 7.0 — 项目说明书

> **阅读对象**：决策层 / 产品 / BD  
> **版本**：v7.0（2026-03-24）  
> **与 6.0 的关系**：**Miner 7.0 在 Miner 6.0 的架构上迭代**，保留「三级数据采集管道 + 10 维 SPS + BD 工作台 + 双轨进化」主线；新增 **BIO 校验增强、圈层影响力（替代粉丝占比）、误杀复盘与 Seed 持续进化** 等能力。技术实现见 [CraftifyX-Miner-7.0-开发实现方案.md](./CraftifyX-Miner-7.0-开发实现方案.md)。

---

## 一句话定位

一套**每月约 500 美元以内**、**4 周可交付 MVP**、**越用越准**的 AI 自动化系统：帮助 CraftifyX **每天产出约 300–500 名带 SPS 评分的海外创作者候选人**，让 BD 专注「判断」与「联系」；系统通过 **BD 反馈 + 销售数据** 双轨进化，并可选沉淀 **误杀案例** 持续优化 BIO 策略。

## 一、核心数字

| 指标 | 数值 | 说明 |
|------|------|------|
| **日终局产出（深度 + 评分）** | **300–500 名创作者** | L3 深度抓取 + 10 维 + SPS 后的 BD 可见候选人规模 |
| **L1 日扫描量** | 约 **5,000** 人级 | Following 浅扫（量级随锚点数配置变化） |
| **L2 AI 过滤后** | 约 **500–800** 人/日 | 规则快筛 + LLM 后的中间池，再进入深度队列 |
| **月发现量（去重后）** | 约 **10,000–15,000** | 覆盖 VTuber / OC / 游戏开发者等；含随机探索 |
| **月度总成本** | **≤$500**（约 ¥3,500） | Apify + 国产大模型 + 服务器 + 数据库等 |
| **交付周期（MVP）** | **4 周** | 数据管道 → BIO → 评分 → Dashboard 上线；完整 Multi-hop / 误杀库增强可分阶段 |
| **预计 BD 审核量** | ~450 人/月 | 系统按 Hub/Connector、SPS 等排序后的高优池（示例口径） |
| **BIO 目标** | 综合准确率 **>90%**；误杀率持续压降 | 依赖规则 + LLM + 可选复盘库 |

## 二、6.0 → 7.0：迭代了什么

| 维度 | Miner 6.0（基线） | Miner 7.0（本版） |
|------|------------------|------------------|
| BIO 过滤 | 规则 + LLM 为主 | **BIO 知识库**（Link DNA / 语义矩阵 / Emoji）+ **四级产品叙事**：硬规则快筛 → 语义矩阵 → LLM 灰区 → **可选：误杀复盘库（Few-shot）** |
| 十维第 7 维 | 历史上曾用「粉丝中创作者占比」等 | **圈层影响力**：**被多少已合作 Seed 关注**（`seed_connections`），归一化为 `circle_influence_score`，与 Hub/Connector **同源** |
| 中心度 | Hub / Connector / Peripheral | **保留**，与 7.0 圈层影响力一致 |
| 进化 | Sales → Seed 晋升、权重概念 | **双轨**：BD 反馈优化联系优先级；Sales 驱动 SPS 权重与 Seed 晋升（与 6.0 一致并写清边界） |
| 文档与代码 | 6.0 说明 | **本说明书 + 7.0 开发方案** 为当前主版本；`db/schema.sql` 已按 7.0 字段对齐 |

## 三、系统解决什么问题

### 现状痛点

- BD 手动在 X 上找人，效率低、易疲劳、难量化。  
- 仅靠关键词搜「Artist」**漏掉大量真实创作者**（链接店铺、极简 BIO）。  
- 评分与「是否值得联系」缺乏统一数据语言。  
- **6.0 已解决「自动化发现 + 粗筛」**；**7.0 强化「少误杀、圈层可解释、可持续进化」**。

### Miner 7.0 如何解决（示意）

```
种子与动态锚点 → L1 浅扫（低成本）→ BIO 规则 + LLM（降噪）→ L3 深度（高成本）
       → 10 维 + SPS + 圈层影响力 / 中心度 → BD Dashboard
       → BD / Sales 双轨反馈 → Seed 与策略迭代
```

## 四、五大核心能力

### 能力 1：三层发现引擎（在 6.0 上保留并写清预算语义）

- **Layer-1**：常规扩展 — 从动态锚点抓取 Following（文档与实现中常用 **60%** 级预算占比描述）。  
- **Layer-2**：超级连接器 — 被多个 Seed 共同关注的账号再扩展（约 **30%**）。  
- **反向挖掘**：高价值 Seed 的粉丝中筛创作者（约 **10%**，可与排期绑定为每周数次）。  
- **随机探索**：在锚点选择中预留 **约 10–20%** 用于跨地域 / 跨品类，**与上述 Multi-hop 比例是同一套「发现策略」下的不同切片**，不在此重复相加为 100% 以上。

### 能力 2：BIO 智能筛选（7.0：四级产品叙事 + 工程三级管道）

**工程实现**仍为：**规则快筛（Link DNA + 语义矩阵 + Emoji）→ LLM 灰区兜底**（见开发方案），降低成本。

**产品叙事（四级）**便于对外沟通：

| 级别 | 含义 | 说明 |
|------|------|------|
| **Level A：硬规则 / Link DNA** | 作品集与店铺链接命中 | 高置信「创作者」信号，可跳过或减轻 LLM |
| **Level B：语义矩阵** | 身份 / 动作 / 工具词等 | 与 `bio_rules.yaml` 一致 |
| **Level C：LLM** | 灰区 BIO、「宁漏勿错」策略 | 批量 JSON 输出，国产长上下文模型 |
| **Level D：误杀复盘（可选）** | Missed Gems Library | BD 标记「系统漏掉但高价值」的 BIO，用于 Few-shot / 周更 Prompt，**MVP 可后置** |

### 能力 3：数据化评分 + 轻量中心度

- **10 维**含 **圈层影响力**（Miner 7.0）：**被多少个已合作 Seed 关注**，字段 **`circle_influence_score`（0–100）**，与 **`creator_scores.seed_connections`、Hub/Connector 分层** 同源（详见开发方案公式）。  
- **不再使用**旧版「粉丝样本中创作者占比（fan_creator_ratio）」作为雷达第 7 维。

### 能力 4：双轨进化（与 6.0 一致，7.0 写清）

- **Track 1**：BD 触达与回复结果 → 优化排序与 **Contact Probability**（初版可规则化，进阶为模型）。  
- **Track 2**：`sales_feedback`（GMV 等）→ **SPS 权重校准**、**高 GMV 晋升 Seed**（如 GMV > $1000 等规则，以配置为准）。

### 能力 5：BD 工作台

- 日报、候选人卡片（**10 维雷达 + 中心度 + SPS**）、Interested / Rejected / Deferred、联系与销售录入、成本面板。  
- **7.0 可选**：**「标记误杀」** 入口，写入误杀复盘库，支撑 Level D。

## 五、日产量漏斗（统一口径）

以下为**同一套漏斗的前后环节**，避免与「300–500 / 500–800」混淆：

```
L1：约 5,000 级 Raw（Following 浅扫，随配置波动）
        ↓ BIO 规则 + LLM
约 500–800 人/日 进入「可深度」队列（中间池）
        ↓ L3 深度（Residential、控制成本）
约 300–500 人/日 完成 Profile + 推文样本 + 10 维 + SPS（BD 主审量级）
```

## 六、4 周 MVP 交付计划

| 周次 | 核心交付 | 业务方可感知的变化 |
|------|----------|-------------------|
| **第 1 周** | 数据基座、Webhook、种子入库、Apify 调通 | 种子与原始关注数据可入库 |
| **第 2 周** | `bio_rules` + 规则快筛、`ai_filter`、发现引擎 | 每日有过滤后的候选人进入下游 |
| **第 3 周** | 深度抓取、10 维（含 **circle_influence_score**）、SPS、中心度 | 候选人带评分与 Hub/Connector 标签 |
| **第 4 周** | Streamlit Dashboard、定时任务、成本面板、联调上线 | BD 可日常审核；可选上线误杀标记与复盘表 |

**说明**：完整 **Layer-2 / 反向挖掘 / 误杀 Few-shot** 若排期紧张，可在 **v1.1** 按开发方案迭代清单上线。

## 七、费用与成本口径

- **总预算**：**≤$500/月**（与 6.0 一致）。  
- **Apify** 仍为主要变量（订阅 + 代理流量）；详见 [爬虫方案.md](./爬虫方案.md)。  
- **国产大模型**：在 **Level A/B 规则覆盖大部分 BIO** 的前提下，LLM 仅处理约 **30% 灰区**，月成本常落在 **约 $2–10**；若规则未上线或全量走 LLM，可接近 **$5–20**。对外可用「**约 $5–15/月（视规则覆盖率与模型）**」单一口径。

## 八、技术选型（摘要）

| 决策项 | 选择 |
|--------|------|
| 采集 | Apify（Following / Profile / Tweets 等） |
| 模型 | 国产（阿里云百炼 / Kimi / DeepSeek / 智谱等，OpenAI 兼容接口） |
| 存储 | PostgreSQL |
| 应用 | Flask Webhook + Streamlit Dashboard |
| 十维第 7 维 | **circle_influence_score**（Seed 关注归一化），见 `db/schema.sql` |

**初版不做**：自动代 BD 发私信、多平台全量采集、重图神经网络训练（与 6.0 边界一致，可渐进）。

## 九、风险与应对（摘要）

| 风险 | 应对 |
|------|------|
| Apify 限流 / 成本波动 | 分层代理、日预算上限、队列削峰 |
| BIO 漏判 | 规则库迭代 + LLM Prompt + **可选误杀库** |
| 圈层数据稀疏 | 新候选人 `seed_connections=0` 为常态，依赖 SPS 与其它维；随图扩大逐步显现 |

## 附录：名词解释

| 术语 | 含义 |
|------|------|
| **Seed** | 已验证或高潜创作者；系统从其关系网扩展发现 |
| **SPS** | Seed Potential Score，10 维加权综合分（0–100） |
| **Hub / Connector / Peripheral** | 被 Seed 关注数分层；与 **圈层影响力** 同源数据 |
| **circle_influence_score** | 圈层影响力 0–100 分，由 `seed_connections` 归一化（如 min(100, ×20)） |
| **三级管道** | L1 浅扫 → L2 BIO 过滤 → L3 深度抓取（与 BIO「四级叙事」层次不同，勿混用） |
